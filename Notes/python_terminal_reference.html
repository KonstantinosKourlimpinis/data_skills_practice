Python & Terminal Quick Reference

A cheat sheet for R users learning Python. Covers the terminal commands and concepts you'll actually use.

Why Python uses the terminal

In R, RStudio wraps everything — package installs, environment, file paths. Python has no single dominant IDE, so its setup instructions use the terminal because it works everywhere (VS Code, PyCharm, Jupyter, etc.). Once your environment is set up, you barely touch it — day-to-day work is in notebooks.

pip — Python's package manager

Equivalent of install.packages() in R. Downloads packages from PyPI (like CRAN).

RPython (terminal)
install.packages("ggplot2")pip install matplotlib
library(ggplot2)import matplotlib (inside code)
CRANPyPI (pypi.org)
CommandWhat it does
pip install pandasInstall a package
pip install -r requirements.txtInstall all packages listed in requirements.txt
pip listSee all installed packages
pip freezeList packages with exact versions (useful for sharing)

Virtual environments

In R, packages install globally. In Python, best practice is one isolated environment per project so packages from different projects don't conflict.

CommandWhat it does
python -m venv .venvCreate a virtual environment in a folder called .venv
source .venv/bin/activateActivate it (Mac/Linux) — you'll see (.venv) in your prompt
.venv\Scripts\activateActivate it (Windows)
deactivateTurn it off, return to system Python
Once activated, pip install and python both point to this project's environment, not your system Python.

requirements.txt

A plain-text list of packages your project needs. Lives in the project root. Run pip install -r requirements.txt to install everything at once.

SyntaxMeaning
pandas>=2.0At least version 2.0 — installs latest compatible
pandas==2.0.1Exactly this version — hard pin
pandas~=2.0Compatible with 2.0 — allows patch updates (2.0.x)
pandasNo constraint — installs whatever is latest
For learning projects, >= is fine. For production or team projects, pin everything with == so everyone gets the exact same environment.
